# Owner release checklist

1. Review the source lock, dependency inventory, relevant advisories, test reports and exact build records. Verify the three native CI jobs. Exercise the intended runtime on macOS 13 Intel, macOS 13 Apple silicon and the supported Windows 10 x64 baseline. Newer CI hosts and Rosetta provide additional evidence. On Windows, run `python tests/runtime.py <candidate-directory>` with UCRT64 binutils available. Verify ordinary metadata, both compressed JPEG XL metadata boxes, Unicode filenames and directory traversal, and the application’s provisioning layout with the candidate ZIP.
2. Review the bundled terms and exact corresponding source. Check the ability to rebuild or relink the distributed FFmpeg components as required by LGPL, and review operating system trust or signing restrictions with the owner. Match the Windows FFmpeg and FFprobe link records to the MSYS2 source packages. Resolve the Strawberry Perl WinLibs r8 corresponding-source gap in [the security record](SECURITY.md#windows-exiftool) before enabling Windows upload or finalization. Assess codec patents for the intended distribution.
3. Choose a fresh public release tag and artifact revision. Record the source-tree commit, candidate checksums, CI run, build logs, toolchain and licence decisions. Retain runtime assets and their corresponding source together. A change to any binary, dependency or signing output receives a new revision.
4. On a trusted host, the owner extracts the macOS executable ZIPs to a private staging directory. Apply the CasaMemo release signing, notarization and Gatekeeper verification procedure to the appropriate deliverable. Use official platform tooling and keep signing materials outside this repository. Follow the equivalent owner-controlled Windows signature policy for eligible Windows components.
5. Rebuild the versioned runtime ZIPs with the final executable bytes and the original build records, paths and notices. Preserve the regular-file attributes and executable mode. From the unpacked
   package root, `find bin build licenses -type f -print | LC_ALL=C sort | zip -X "$final_zip" -@`
   creates the archive with regular-file entries when `final_zip` is a new absolute output path. The published ExifTool TAR.GZ retains the exact upstream archive bytes. Generate the final index after signing and any other byte-changing work. The tooling only describes and verifies local files.
6. Run `python3 scripts/artifacts.py finalize-index <platform> <staging-directory> --revision r1` and `python3 tests/runtime.py <staging-directory>` for each native platform. `owner-finalized` identifies when hashes were refreshed. Confirm the signing, licence and release gates separately. Check `SHA256SUMS` and the application provisioning layout against the exact candidate.
7. The owner publishes the reviewed runtime archives, corresponding source archives, per-platform index and SHA-256 lists to an immutable GitHub Release. Preserve each platform's index and sums under distinct public asset names. Download every published file from the intended URL and verify size and SHA-256 against the reviewed final index. Verify provisioning using a test application environment before selecting assets in the production manifest.

CI uploads unsigned macOS candidates to Actions for inspection. Windows CI provides build and test evidence. Windows binary uploads and local finalization are withheld pending corresponding-source review and native Windows 10 acceptance. Release preparation and publication are owner-controlled. Retain public source for as long as the associated binaries are available, subject to any longer licence obligations. Preserve support for old approved download URLs and use a subsequent revision for fixes.
